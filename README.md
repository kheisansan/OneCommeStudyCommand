# 教育辞書プラグイン

わんコメの読み上げへ、ユーザーが登録した単語と読みを適用するプラグインです。
コメントから単語を教育できるほか、プラグインの管理画面から辞書の追加、削除、優先度変更ができます。

## 対応環境

- わんコメ 5.2以降

## インストール

### 新規インストール

1. リリースZIPを解凍します。
2. 解凍された `onecomme-study-command-plugin` ディレクトリを、わんコメのプラグインディレクトリへ配置します。
3. わんコメを起動し、「教育辞書プラグイン」を有効にします。

### バージョン更新

> [!CAUTION]
> 既存のプラグインディレクトリを丸ごと置き換えると、登録辞書を保存している `state.json` が削除されます。更新前に `state.json` を別の場所へ退避してください。

> [!IMPORTANT]
> `v0.4.1` 以前から更新する場合、`v0.4.2` でプラグインUIDが変更されます。更新後にプラグインが無効になっている場合は、プラグイン一覧から再度有効にしてください。旧版を別ディレクトリに残さず、既存のプラグインディレクトリへ上書きしてください。

1. 既存のプラグインディレクトリにある `state.json` を別の場所へ退避します。
2. リリースZIPを解凍します。
3. 既存のプラグインディレクトリを削除せず、解凍したファイルを既存ディレクトリへ統合する形で上書きします。
4. 既存の `state.json` が残っていることを確認します。ディレクトリを置き換えた場合は、退避した `state.json` を元へ戻します。
5. プラグイン一覧で「教育辞書プラグイン」が1つだけ表示され、有効になっていることを確認します。
6. 管理画面を開き、登録済みの辞書と設定が維持されていることを確認します。

変更は即時反映されます。反映が気になる場合は、わんコメのプラグインメニューから「更新」を押してください。

## コマンド

### 単語を教育する

```text
教育(単語=読み)
```

例:

```text
教育(FF14=えふえふじゅうよん)
```

同じ単語をもう一度教育すると、登録済みの読みを更新します。
半角・全角の括弧とイコールを使用できます。

### 単語を忘却する

```text
忘却(単語)
```

例:

```text
忘却(FF14)
```

### 共有辞書へ申請する

共有辞書を設定している場合、チャットから共有辞書への申請ができます。

```text
共有教育(単語=読み)
共有忘却(単語)
```

- `共有教育` は自分の辞書へ登録し、同時に共有辞書へ追加を申請します
- `共有忘却` は自分の辞書から削除し、同時に共有辞書からの削除を申請します
- どちらもオーナーが承認するまで共有辞書には反映されません
- 実行した視聴者の表示名が投稿者名として申請に添付されます

共有辞書が未設定の場合は「共有辞書が設定されていません。」と読み上げられます。管理画面の設定でコマンド単位の無効化もできます。

### 共有辞書の申請を承認・却下する (モデレータのみ)

共有辞書のモデレータとして登録している場合、自分の配信チャットから承認待ちの申請を処理できます。

```text
共有承認(単語)
共有却下(単語)
```

- **配信者本人のコメントのみ**有効です (視聴者が入力しても無視されます)
- モデレータ登録は管理画面「共有辞書」→「モデレータ」で、オーナーから伝えられたパスワードを入力して行います
- 管理画面の「承認待ちの申請」一覧からボタンで処理することもできます

## 管理画面

わんコメのプラグイン一覧から「教育辞書プラグイン」の管理画面を開きます。

管理画面では次の操作ができます。

- 教育・忘却・共有教育・共有忘却の各コマンドの有効・無効を切り替える
- 単語と読みを入力して辞書へ追加する
- 登録済みの項目を削除する
- 登録済みの優先度を変更する
- 棒読みちゃんの教育辞書をインポートする
- 共有辞書から項目を選んで取り込む・新しい変換を投稿する

優先度を変更すると、その行に「保存」ボタンが表示されます。`Enter` で保存し、`Escape` で保存済みの値へ戻せます。

### 棒読みちゃん教育辞書のインポート

管理画面の「棒読みちゃん教育辞書のインポート」から、棒読みちゃんの `ReplaceStudy.dic` を選択します。
保存前に、追加予定、同一項目の統合、既存項目のスキップ、エラーの各件数を確認できます。

インポート対象は、棒読みちゃんの教育コマンドで登録された単純置換だけです。Word辞書、Talk辞書、正規表現辞書には対応していません。

- 既存の教育辞書は変更せず、同じ単語はインポート側をスキップします
- ファイル内の同じ単語に異なる読みがある場合や、形式にエラーがある場合は保存しません
- ファイル内容は外部サービスへ送信せず、ローカルで動作するプラグインの管理APIだけへ送信します

### 共有辞書

コミュニティで管理する変換辞書 (Google Spreadsheet + Google Apps Script) から、項目を選んで自分の教育辞書へ取り込めます。

1. 管理画面「共有辞書」の「共有辞書URL」に、共有辞書のウェブアプリURLを入力して保存します。
2. 「共有辞書を更新」で一覧を取得します。取得結果は1時間キャッシュされ、ボタンで手動更新できます。
3. 取り込みたい項目にチェックを入れ、「選択した項目を取り込む」を押します。同じ単語が既に登録されている項目はスキップされます。

新しい変換の投稿もできます。投稿は共有辞書のオーナーが承認するまで公開されません。「投稿状況」の「状況を更新」で承認・却下の結果を確認できます。

- 投稿できるのは単純置換のみです (単語100文字・読み200文字まで、制御文字は不可)
- 短時間の連続投稿や、同じ単語の重複投稿は受け付けられません
- 投稿にはプラグインが自動生成した匿名トークンが添付されます (名前を残したい場合は投稿者名を入力してください)

共有辞書そのものを運営する場合のセットアップ手順は [gas/README.md](./gas/README.md) を参照してください。

## 優先度

初期優先度は、表記を正規化した単語の文字数です。通常は長い単語が先に置換されます。

管理画面で優先度を変更した場合は、文字数よりユーザー指定の優先度を先に扱います。辞書一覧も実際の置換順に表示されます。

置換順は次のとおりです。

1. 優先度が高い項目
2. 単語が長い項目
3. 更新日時が古い項目
4. 登録順が早い項目

## 開発

### 必要な環境

- Node.js 24 LTS
- npm
- リリースZIPを生成する場合は `zip` コマンド

依存関係をインストールします。

```sh
npm ci
```

TypeScriptをビルドします。

```sh
npm run build
```

ビルドと自動テストを実行します。

```sh
npm test
```

`dist/`、`release/`、`node_modules/` は生成物またはローカルファイルです。直接編集・コミットしないでください。

### リリースZIP

開発確認用のZIPは、更新種別を明示して生成します。

```sh
npm run release:dev -- patch
```

本番用ZIPは、安定タグ以降にコミットがあり、作業ツリーがcleanな状態で生成します。

```sh
npm run release:prod -- patch
```

更新種別には `major`、`minor`、`patch` のいずれかを指定します。バージョンは到達可能な最新の安定タグ `vX.Y.Z` から計算されます。リリース処理はコミット、タグ作成、pushを行いません。

安定タグを付けた後、そのタグと同じバージョンのZIPとSHA-256チェックサムを生成できます。

```sh
npm run release:tag -- v0.4.1
```

タグ用リリースは、指定した安定タグが現在のHEADを指し、作業ツリーがcleanな場合だけ生成されます。

### GitHub Release

GitHubのActions画面から `Release` workflowを選び、公開する安定タグを入力して手動実行します。

workflowは対象タグの全履歴を取得し、依存関係のインストール、自動テスト、ZIPとSHA-256チェックサムの生成を行います。成功すると、成果物を添付したDraft Releaseが作成されます。

Draftの内容と成果物を確認してから、GitHub上で公開してください。同じタグのReleaseが既に存在する場合、成果物は上書きされません。

## コントリビューション

不具合報告や改善提案はGitHub Issuesで受け付けます。変更を提案する場合は、先にIssueで目的と影響範囲を共有してください。

プルリクエストでは、関連するテストを追加または更新し、`npm test` が成功することを確認してください。
